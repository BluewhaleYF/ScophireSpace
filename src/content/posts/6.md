# 结识 COSMIC

看了 LTT 的视频才了解到 Pop!_OS 及其桌面环境，当时就被它那种融合了平铺窗口与现代简约美学的设计风格吸引了。但真正让我下定决心在实机上安装的，是它背后的两个先进理念：COSMIC 是少数主要以 Rust 构建、并从一开始围绕 Wayland 设计的完整桌面环境之一，从合成器到上层控件都尽量避开了传统 X11 桌面的历史包袱。

![official image](https://raw.githubusercontent.com/BluewhaleYF/ScophireSpace-Files/refs/heads/main/Posts/6/COSMIC%20official%20demo.webp)

作为一个被 Hyprland 的配置复杂度劝退过的 Linux 用户，这简直是一个完美选项。不用啃文档写配置，就能体验真正原生的 Wayland 平铺体验，还能拥有现代美观的图形界面。光是这个理念，就足够让人兴奋到愿意拿一台老 MacBook 来当小白鼠。

于是昨晚，我在自己的 MacBook Pro 2014 上装了一套试试看。这篇文章没有严谨的 Benchmark，只记录第一天使用下来的一些真实感受。

---

# 惊鸿一瞥

安装速度比想象中快得多，最简安装仅用了几分钟就完成了。

注销 GNOME 会话，重新登录到 COSMIC 后，简单调整了一下主题、壁纸和 Dock 的布局，我几乎立刻就明白了为什么不少人第一次接触 COSMIC 都会留下不错的印象。

最吸引我的还是它的视觉设计。

整个桌面大量运用了半透明与实时模糊效果，却没有给人一种刻意炫技的感觉。启动器、通知中心以及面板上的各种弹出菜单，都采用了相同的设计语言，层层叠叠的窗口配合背景壁纸，很容易营造出一种十分通透的空间感。我第一眼看到时，脑海里甚至冒出了 OS X El Capitan 那个时代的印象，干净、克制，却又不显得单调。

![desktop demo](https://raw.githubusercontent.com/BluewhaleYF/ScophireSpace-Files/refs/heads/main/Posts/6/tiling2.png)


有意思的是，我现在体验 COSMIC 用的，正好也是一台和 El Capitan 同时代的 MacBook Pro。当这种带着一点苹果味道的视觉设计重新出现在这块 Retina 屏幕上时，总让我产生一种说不上来的熟悉感。

浅色主题倒是让我有一点遗憾。按理说这种设计应该呈现出一种带着轻微模糊感的纯白质感，但目前默认配色略微偏灰，少了几分通透，多了一点沉闷，相比深色主题明显逊色一些。

活动窗口的高亮边框也是我最喜欢的细节之一。当前窗口会被一圈纯色边框轻轻勾勒出来，没有阴影，也没有复杂的特效，看起来反而格外干净。这种设计让我想起了 Hyprland 默认的活动窗口边框，简单到几乎只有一圈纯色描边，却一下子让整个桌面的气质变得很现代，窗口焦点也因此一目了然。

这套视觉效果如果放到 Hyprland 或 Niri 上，大概要花不少时间翻 Wiki、改配置，再不断调整模糊半径、透明度、动画曲线这些参数才能得到差不多的效果；COSMIC 把这些选项直接放进了图形设置里，安装完成后几乎不用继续折腾，只需要动几个滑块，就已经有很高的完成度。

整个设置界面的布局也很舒服，没有为了追求"高级感"把各种选项藏得很深，常用功能基本都能在两三次点击内找到。第一次接触 COSMIC，我几乎没有花什么时间适应它的设置逻辑。

这种开箱即用的体验，也让我第一次觉得，平铺桌面其实没有想象中那么难上手。

COSMIC 也没有把自己定位成一个纯粹的平铺桌面。它同时保留了平铺与堆叠两种工作方式，需要整理窗口的时候可以切换到平铺模式，平时也能继续按照传统桌面的习惯使用，两种模式之间的切换非常自然。

我还特别喜欢它的全局搜索。按下 Super 键之后，无论是搜索应用、文件还是执行一些简单操作，都能够很快得到结果，整个过程几乎不会打断当前的操作节奏。虽然类似的设计已经存在于不少桌面环境中，但配合 COSMIC 本身的视觉效果，实际用起来依旧十分舒服。

不过，当我真正开始把它当成日常桌面使用之后，这份惊艳很快就被现实拉了回来，其中最明显的问题，就是性能。

---

# 令人失望的流畅度

即使保持默认配置，整个桌面依然卡得很明显。比我日常使用的 GNOME 还要卡得多，甚至连鼠标指针移动都会明显掉帧，已经影响到了正常操作。当然考虑到 COSMIC 目前仍处于开发阶段，COSMIC 基于 Rust 和 Iced 构建的图形界面，目前似乎还没有针对这块 Intel Haswell-ULT 老集显做好充分优化，倒也意料之内。

想起几天前我在 KVM/QEMU 里装 Pop!_OS 虚拟机时，也遇到过类似的问题。我给虚拟机分配了 10 个 vCPU 和 8 GB 内存，界面依然卡顿严重，窗口移动时甚至会出现大面积撕裂，画面几乎被切得到处都是（这不是夸张）。不过，这也可能与 VirGL/SPICE 对 COSMIC 图形栈或 Iced 渲染路径的兼容性有关。

---

# 试图挣扎优化

后来折腾了一会，体验稍微好了那么一点。

这台 MacBook Pro 配备的是 Haswell 核显，却要驱动一块 2560 × 1600 的 Retina 屏幕。我日常为了兼顾显示面积和字体大小，一直使用 166.67% 非整数缩放。显示效果和流畅度都比较理想。

不过切换到 COSMIC 后，系统并没有提供这一档缩放比例，自动改成了 175%，因此 GPU 的负担也进一步增加了。

GNOME 对这种场景已经优化得比较成熟，而 COSMIC 目前显然还有不少工作要做，因此老机器上的掉帧会更加明显。

查了一些资料之后，我尝试开启了 Intel i915 驱动的两个特性。

```bash
sudo nano /etc/modprobe.d/i915.conf
```

写入：

```text
options i915 enable_psr=2 enable_fbc=1
```

其中：

- `enable_psr=2`：启用 Panel Self Refresh（PSR）
- `enable_fbc=1`：启用 Framebuffer Compression（FBC）

重启之后，虽然距离流畅还有一段距离，但鼠标移动和窗口动画多少顺了一些，至少没有最开始那么难以使用。

当然，这更像是一种缓解，并没有从根本上解决 COSMIC 当前在 Haswell 核显上的性能问题。

---

# 仍然难以解决的细节优化问题

相比整体性能，更让我摸不着头脑的是鼠标指针的卡顿。

一开始我以为是整个系统都掉帧，但实际使用下来发现情况并没有这么简单。

鼠标指针的卡顿是有条件出现的：在 COSMIC 桌面、设置等自带应用中，移动鼠标时掉帧十分明显；而一旦打开 GTK 应用，无论是移动还是悬停，都明显流畅许多，几乎恢复到了 GNOME 下的体验。

目前我还没有找到原因，只能做一些猜测。GTK 应用很可能走的是另一套已经比较成熟的渲染路径，而 COSMIC 自身基于 Iced 的渲染管线，对于 Intel Haswell 这一代老核显的优化仍然不够完善，因此两者在同一台机器上的流畅度出现了明显差异。

当然，这只是我根据现象做出的推测，并没有进一步分析渲染日志或 GPU Profiling。如果后续找到更准确的原因，我会回来更新这篇文章。

---

# 粗糙的 i18n

中文本地化目前也比较粗糙，系统界面中仍有大量元素没有翻译，已经完成翻译的字符串质量也不太稳定。字体回退问题更加明显，同一句话里可能同时出现多套字体，粗细、基线和字形风格都不统一，简体中文、繁体中文以及日韩字体混在一起时，观感尤其凌乱。

想要解决也不困难，只需要手动去设置里把系统字体强制切成 Noto Sans CJK SC，就能达到合格的观感。

好在 Fcitx5 的兼容性相当不错，候选框、输入状态切换和中文输入都能正常工作，暂时没有遇到明显异常。相比之下，我之前在 Cinnamon 上使用 Fcitx5 时经常碰到候选框位置不对、部分应用无法正常呼出输入法之类的问题，COSMIC 在这一点上反而省心不少。

# 总结

第一天的体验还不足以评价 COSMIC 的全部水平，但已经足够让我理解为什么它最近会受到这么多关注。至少在交互设计和整体理念上，它确实有不少让我眼前一亮的地方。

不过，至少在这台使用 Haswell 核显的老 MacBook Pro 上，它目前的性能还无法满足日常使用需求。鼠标指针和原生应用频繁掉帧，非整数缩放的选择也不够灵活，所以我最后还是切回了 GNOME，先保证基本的流畅度。

毕竟这是一个非常年轻的 DE，优化还需要时间。对 System76 后续打磨保持乐观，毕竟交互理念和配置逻辑确实切中了我日常需求，假以时日，COSMIC 完全有潜力成为我的主力 DE。

COSMIC 目前暴露出来的问题，大多集中在性能优化、本地化和应用适配上，这些都需要后续版本继续打磨。我最初喜欢的那套交互思路和设计理念，也没有因为这些问题失去吸引力。等性能和细节成熟一些之后，我很愿意再回来试一次。
